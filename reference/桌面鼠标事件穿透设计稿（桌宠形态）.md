# 桌面鼠标事件穿透设计稿（桌宠形态）

> 2026-11-06 · 方案 C 定稿 · 状态：**设计完成，未开工**
> 前置实证：透明窗形态（NOFRAME+TRANSPARENT）已在 pygamest-dev 300 帧跑通
> （透明呈现修复链见 starfish 1593776 + pygamest-dev 8a37db0）

## 一、背景与目标

桌宠形态 = 无边框（NOFRAME）+ 逐像素透明（TRANSPARENT，`WS_EX_NOREDIRECTIONBITMAP`
+ DxgiFromVisual 呈现）窗口常驻桌面。缺的最后一环是**鼠标事件穿透**：

- 宠物窗口不遮挡桌面点击（穿透态）；
- 可随时切换回可交互（非穿透态）；
- 进阶形态：**逐像素动态穿透**——鼠标悬在宠物不透明像素上可交互，
  悬在透明像素上自动穿透（桌宠交互体验的核心）。

## 二、方案对比与结论（方案 C = 混合分层）

| 方案 | 内容 | 结论 |
|---|---|---|
| A. starfish-we 内全量 | 窗口能力位 + 全部穿透逻辑进核心仓 | 简单布尔场景合适；桌面增强族（热键/托盘/逐像素命中）持续进核心 = 污染 |
| B. 全量独立 crate | 不碰 starfish-we | 简单布尔开关也要新依赖，90% 用例过重 |
| **C. 混合（定稿）** | **starfish-we 只加窗口能力位（布尔开关，与 always_on_top 同构）；独立桌面增强库承载智能穿透调节器** | 简单场景一行 API；复杂场景独立演进；能力位本就是垫底原则的管理对象，无"跨平台名分"问题 |

关键事实：`starfish_we::Window::raw_handle()` **已是 pub**（window.rs:234，
返回 `RawWindowHandle::Win32 { hwnd, hinstance }`）——独立库起步零改动
starfish-we。

## 三、平台机制矩阵（点击穿透的实现原语）

| 平台 | 机制 | 实现量 | 备注 |
|---|---|---|---|
| **Windows**（首实装） | `SetWindowLongW(hwnd, GWL_EXSTYLE, ex \|=`<br>`WS_EX_LAYERED \| WS_EX_TRANSPARENT)`；关闭=清位 | ~20 行 FFI | 与 `WS_EX_NOREDIRECTIONBITMAP`（透明呈现）共存无冲突——只改命中测试，不改 DWM 合成 |
| **macOS**（后置） | `NSWindow.setIgnoresMouseEvents(bool)` | ~10 行 objc | 属性任意切换 |
| **Linux/X11**（后置） | `XShapeCombineRectangles(ShapeInput, 空区)` | ~15 行 | 空输入区=整窗穿透；**resize 后需重挂** |
| **Linux/Wayland**（后置） | `wl_surface.set_input_region(empty)` | ~10 行 | 部分合成器"穿透到桌面"而非"穿透到下层窗口"——文档标注平台差异 |
| **Web/Android/iOS** | ✗ 无此概念 | — | 垫底原则：静默忽略（与 ALWAYS_ON_TOP 同款） |

## 四、第一层：starfish-we 窗口能力位（简单场景）

### 4.1 API 设计（与 set_always_on_top / set_borderless 同构）

```rust
// starfish-we window.rs（runtime 方法族——创建线程直接可用）
impl Window {
    /// 鼠标事件穿透开关（点击穿透：本窗口命中测试跳过，事件落下层）。
    /// Windows = WS_EX_LAYERED|WS_EX_TRANSPARENT 位；macOS =
    /// setIgnoresMouseEvents；X11 = 空输入区；不支持的平台 Err 垫底
    /// （垫底原则——与 ALWAYS_ON_TOP 同族能力位）。
    pub fn set_click_through(&self, enable: bool) -> Result<(), WindowError>;
    /// 当前穿透态查询（防自锁——穿透后窗口收不到鼠标，脚本侧须能
    /// 读态确认/由外部逻辑恢复）。
    pub fn is_click_through(&self) -> bool;
}
```

- 平台实现落 `platform/<os>/mod.rs`（Win32 首实装；mac/linux 待各自
  窗口后端落地时跟上；android/ios/web 直接 Err）
- 不新增 feature——FFI 本就按 `target_os` cfg 天然分平台，量级小
- 状态存 `WndState`（与 opacity/visible 同款字段）

### 4.2 starfish-pygame / pygamest 绑定面

```rust
// starfish-pygame display.rs
pub fn set_click_through(enable: bool) -> Result<(), ...>;  // get_screen() 转发
pub fn get_click_through() -> bool;
```

```python
# pygame.display 扩展 API（pygame 无同名惯例，标注为引擎扩展）
pygame.display.set_click_through(True)
pygame.display.get_click_through()   # False/True
```

- 与 `apply_window_request`/`apply_window_flags` 正交（穿透是运行期
  状态，不进创建期 flags/KNOWN_MASK）
- 宿主预建窗形态（pygamest-dev 800×600 惯例）下同样工作：走 SCREEN
  槽 window 引擎句柄，与 set_mode 流程解耦

## 五、第二层：独立桌面增强库（智能穿透，桌宠核心）

### 5.1 仓定位

- **新仓**，不带 starfish 跨平台名分：`we-desktop-kit`（备选
  `desktop-pet-kit` / `we-window-extras`）。Cargo description 明写
  `desktop-only (windows-first; macos/linux planned)`
- 依赖：`starfish-we`（拿 `raw_handle`）+ `windows-sys`（win 首实装）
  + `objc2`/`x11rb`/`wayland-client`（各自 target-gated，后置）
- 版本独立演进；桌面专属能力族的家（点击穿透 → 热键 → 托盘 →
  桌面交互件）

### 5.2 分层 API

```rust
// ── 第 0 层：布尔开关（薄封装——第一层能力位的库侧形态）──
pub struct DesktopWindow { /* 持 starfish_we::Window 句柄 */ }
impl DesktopWindow {
    pub fn from_starfish(w: &starfish_we::Window) -> Result<Self, KitError>;
    pub fn set_click_through(&self, enable: bool) -> Result<(), KitError>;
    pub fn is_click_through(&self) -> bool;
}

// ── 第 1 层：智能穿透调节器（桌宠核心——逐像素动态穿透）──
pub struct ClickThroughController { /* ... */ }

/// alpha 探针抽象（"光标处是否透明"的三种来源）
pub enum AlphaProbe {
    /// a) Surface CPU alpha 影子（from_rgba8 路径现成——零 GPU 回读）
    CpuAlpha { surface: Surface, ppm: (f32, f32) },
    /// b) 单点 GPU 回读（readback_probe 的 1 点版；60fps 可承受）
    GpuPointReadback { screen: Screen },
    /// c) 不透明矩形清单（最省——桌宠形状脚本侧本已知）
    Rects(Vec<(f32, f32, f32, f32)>),
}

impl ClickThroughController {
    /// 挂调节器：cursor 命中处 alpha==0 → 穿透 ON；非透明 → OFF。
    /// hotkey = 窗口外恢复通道（穿透态窗口收不到鼠标——RegisterHotKey
    /// win 首实装），必配防自锁。
    pub fn attach(w: &starfish_we::Window, probe: AlphaProbe,
                  hotkey: Option<Hotkey>) -> Result<Self, KitError>;
    /// 每帧调用（或内部定时器）：光标命中判定 → style 位切换（仅在
    /// 状态变化时 SetWindowLong——零抖动）
    pub fn pump(&mut self);
    /// 事件出口（穿透态进入/退出，脚本可感知）
    pub fn drain_state_changes(&mut self) -> Vec<bool>;
}
```

### 5.3 调节器工作细节

- **判定**：`GetCursorPos` → 换算窗口客户区坐标 → probe 查 alpha
  → 目标态 != 当前态才 SetWindowLong（位写是廉价原子操作，但每帧
  重复写会造成命中测试抖动，必须状态变化才写）
- **热键**：`RegisterHotKey(hwnd, id, MOD_CONTROL|MOD_ALT, 'P')` →
  消息泵收 WM_HOTKEY → 强制退出穿透态（自锁恢复通道）
- **窗口移动跟随**：窗口被拖动/脚本移动后 alpha 探针的坐标系同步
  （probe 以客户区坐标为准，天然跟随 ✓）

## 六、边界与坑（文档必写 + 实现必查）

| # | 坑 | 处置 |
|---|---|---|
| 1 | **穿透自锁**：穿透后窗口收不到任何鼠标——点不到、拖不动 | API 必配 `is_click_through()` 状态查询；kit 层必配热键恢复通道；文档置顶警告 |
| 2 | **DComp 共存** | `WS_EX_TRANSPARENT` 只改命中测试，透明呈现不受影响——已在 pygamest-dev 透明窗实证路径上 ✓ |
| 3 | **键盘焦点** | WS_EX_TRANSPARENT 连点击激活一起穿透：穿透态窗口永不获焦，键盘输入收不到——有键盘交互需求的桌宠须切回交互态 |
| 4 | **X11 resize 输入区失效** | resize 后输入区需重挂——kit 层监听 resize 重挂（X11 后置时处理） |
| 5 | **Wayland 合成器差异** | 空输入区在部分合成器上"穿透到桌面"而非"穿透到下层"——平台差异文档标注 |
| 6 | **宿主预建窗** | pygamest-dev 宿主壳 800×600 预建（创建期旗标预扫描见 runtime.rs）——穿透是运行期状态走 SCREEN 槽句柄，正交不受影响 |
| 7 | **每帧重复位写抖动** | 调节器必须状态变化才 SetWindowLong，防命中测试抖动 |
| 8 | **多窗未来** | 能力位按 window 实例隔离（WndState 字段），天然支持多窗（桌宠+控制小窗形态） |

## 七、里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M1** | starfish-we `set_click_through`/`is_click_through`（Win32）+ starfish-pygame 转发 + pygame.display 两口 | 透明窗 demo 上 `set_click_through(True)` 后点击落到下层窗口；查询态正确；常规 demo 回归不破 |
| **M2** | `we-desktop-kit` 新仓：DesktopWindow + attach/pump + Rects probe + win 热键 | 桌宠 demo：宠物透明区点击穿透、非透明区可拖动交互、热键强制恢复 |
| **M3** | CpuAlpha / GpuPointReadback probe + 逐像素动态穿透 | 悬停透明像素穿透、悬停不透明像素交互的动态切换实录 |
| **M4** | macOS / Linux(X11) 后端 + Wayland 文档 | 平台矩阵全绿 |

## 八、定约沉淀

1. **穿透是运行期状态**——不进创建期 flags/KNOWN_MASK（与 always_on_top
   的创建期+运行期双形态不同：穿透依赖渲染先行，创建期无意义）
2. **能力位垫底原则**复用：不支持平台 Err/忽略，不硬编码平台分支到调用方
3. **防自锁三件套**：状态查询 API + kit 热键 + 文档置顶警告——缺一不可
4. **starfish-we 只背能力位**：桌面增强族一律进独立库（we-desktop-kit），
   核心仓不收热键/托盘/全局钩子类能力
