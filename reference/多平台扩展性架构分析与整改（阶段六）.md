## 一、架构分析（6.1）

### 1.1 平台抽象层现状（承载力评估）

- **窗口/输入**：`starfish-we` 门面（`window.rs`）+ `platform/<os>/`
  目录制——每平台实现**同一组内部契约**（`poll_event` 非阻塞泵 /
  事件翻译 `translate.rs` / 物理像素边界换算 / `rwh` 裸窗口句柄直通
  wgpu）。AppKit 后端证明该契约可承载"主线程亲和 + 委托回调"型
  系统；Android 后端证明可承载"系统掌管入口 + 缓冲队列反转"型系统。
  **HarmonyOS 的 XComponent/NativeXComponent 回调模型与 Android
  native_app_glue 同构**——接入模式有现成模板。
- **渲染**：wgpu 一层抽象，后端按目标自动选择（DX12/Vulkan/GL/
  WebGPU/Metal）。`AutoSurface`（wgpu-auto feature）接管
  resize→configure 对账循环——平台无关。macOS/iOS 的 Metal 路径
  **零新增代码**即可用。
- **音频**：`starfish-audio` device 模块 = cpal 胶水，头注释明示
  "平台差异唯一收敛点……其他平台按此接口实现"——**trait 接口即
  扩展点**（OHAudio 实现该接口即可，无需动混音层）。
- **视频**：`starfish-video` 平台后端目录制（windows/linux/apple/
  web/android 五后端 + mp4_demux/yuv/player 平台中立共享层），
  `VideoError::UnsupportedPlatform` 站桩语义齐备。
- **字体/文本/2D 光栅**：starfish-font + vello_common（CPU 光栅）
  平台中立（Android 实证含 NaN 防御补丁）。
- **io**：std::fs（原生）+ fetch/XHR（web）单源路由（sfx::read）；
  macOS/iOS 沙箱路径为参数级差异（base_dir 已统一）。

### 1.2 平台强耦合点识别（与平台绑定的代码）

| 耦合点 | 位置 | 性质 |
|---|---|---|
| Win32 位操作（skip-taskbar/click-through） | starfish-we platform/windows | 平台后端内聚，门面 cfg feature 透传 ✅ |
| SAF/InMemoryDexClassLoader（dialog 退役） | starfish-dialog | 已从 pygamest 剔除（维护面收敛）✅ |
| MediaCodec JNI（video android） | starfish-video android.rs | 后端内聚 ✅ |
| MF SourceReader file:/// 规范化 | starfish-video windows.rs | 后端内聚 ✅ |
| gfxstream GLES base_vertex 规避 | pygame_live2d | **GL 实现栈差异**——OHOS/GL 后端同需关注 ⚠️ |
| 打包脚本（build_windows/wasm/android） | pygamest-runtime scripts | **真实缺口**（本阶段整改位） |
| wgpu 30.0.1 上游 OHOS 缺位 | 依赖树 | vendor patch 或 GL 后端定制 ⚠️ |

### 1.3 可复用 vs 需抽象

- **直接复用（零改动）**：starfish-std（letterbox/math）、
  starfish-font、vello 光栅、starfish-render 管线/材质层、
  starfish-pygame 全部绘制词汇、pygamest 绑定层（RustPython 嵌入
  平台中立）、FRAME_BRIDGE 调度、starfish-io 路由、starfish-net
  （原生 TCP 路径 macOS/iOS/OHOS 直用）。
- **已有实现待接线**：macOS/iOS 窗口+输入+视频——补打包链即到
  "可构建"态。
- **需新增适配**：OHOS 窗口/输入（XComponent）、渲染（wgpu GL/EGL
  或 vendor）、音频（OHAudio device trait 实现）、视频（AVPlayer
  NDK 后端）、打包（hap/hvigor）。

## 三、整改方案与落地（6.3）

**落地项（本阶段完成，纯增量零回归）**：

1. **打包管线配置化**：`pygamest-runtime/scripts/build.py` builders
   表增加 `reserved` 扩展位（macos/ios/ohos）——调用输出明确
   "[预留] 打包适配层待建"提示；新平台打包脚本就绪后登记本表即可，
   总控零改动。
2. **扩展点位置文档化**（本报告 + docs-zh 新平台扩展指南）：
   - 窗口/输入：`starfish-we/src/platform/<os>/` 目录制（门面契约 =
     poll_event 泵 + translate 翻译 + rwh 句柄）
   - 视频：`starfish-video/src/<os>.rs` 后端目录制（DecodedFrame/
     FramePixels 统一输出契约）
   - 音频：`starfish-audio/src/device` trait 实现
   - 打包：`build_<os>.py` 登记 runtime builders 表
3. **不落 OHOS 代码骨架的理由**：`target_env="ohos"` cfg 值需实测
   rustc 元数据定型（写错 = 永不编译的死代码或误伤 linux 构建的
   风险），待 OHOS SDK 环境建立时随首个真实构建一并落位——报告
   已给出精确接入清单，架构不成阻碍。

**明确不做**（约束遵守）：不为预留而预写不可验证的 cfg 门控代码；
不动既有三平台任何路径（本次改动 = build.py 追加字典键 + 文档）。

## 五、OHOS 实测定型与分流桩落地（2026-11-11 续）

### 5.1 rustc 元数据实测（`rustc --print cfg --target aarch64-unknown-linux-ohos`）

```text
target_os  = "linux"     ← OHOS 目标的 target_os 是 linux！
target_env = "ohos"
target_family = "unix"
```

**关键发现**：不分流时，OHOS 构建会**静默吞下所有 `cfg(target_os =
"linux")` 分支**——starfish-we 走 Wayland 后端（OHOS 无 Wayland 合成
器）、starfish-video 走 GStreamer（OHOS 无 GStreamer）、starfish-audio
经 cpal 拉 ALSA（alsa-sys 构建脚本实证失败）。**显式分流是 OHOS 接入
的第一步**，否则"站桩语义"根本不成立。

### 5.2 分流桩落地（本节为代码级整改，已 check 实证）

| 仓/文件 | 改动 | 门 |
|---|---|---|
| starfish-we `platform/mod.rs` | linux 门控 → `all(target_os="linux", not(target_env="ohos"))`；新增 `harmonyos` 分流（`all(linux, ohos)`） | 原生/OHOS × 有无 features 四门全绿 |
| starfish-we `platform/harmonyos/mod.rs` | **OHOS 站桩**：`WindowInner` 刻意不可构造（uninhabited enum——类型系统编码"OHOS 尚无窗口"），全部 53 项契约方法 `match *self {}` + `new()` 恒 `OsError("…适配层待建…")`；click-through/skip-taskbar/tray 三组 feature 门控镜像 linux 形态 | 同上 |
| starfish-we `Cargo.toml` | linux 依赖门（wayland/sctk/libc/tray-icon）排除 ohos | OHOS check 不再拉 Wayland 链 |
| starfish-we `tray.rs` | 三桌面排水/转换门控摘 OHOS + 导入随门控走 | OHOS check 零 unused |
| starfish-video `Cargo.toml` + `lib.rs` | GStreamer 依赖与 `mod linux` 门控摘 OHOS；`open_backend` 新增 OHOS 臂 → **`VideoError::UnsupportedPlatform`** 设计站桩 | 原生 check 0 error |
| starfish-audio | **不割**——cpal 触点多（device/record/stream），OHAudio device trait 实现是真适配层第一项（接口即扩展点，lib.rs:15 明示"其他平台按此接口实现"）；OHOS check 卡点 = `alsa-sys` 构建脚本（实证记录在案） | — |
