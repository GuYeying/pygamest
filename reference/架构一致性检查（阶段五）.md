## 二、架构债清单（记录非阻断）

### A-1 管线缓存放置：绑定层 vs 引擎执行器

**现状**：1.4 管线缓存实现在 pygamest `PyRawPass` 记录制（同一
`Pipeline` Arc 指针 / 同 slot 同 `BindGroup` 指针跳过冗余命令，管线
变更清 bind 缓存）。

**定约张力**："starfish-pygame 完成实现，再对接 pygamest" 字面上要求
去重发生在引擎层（`starfish_render::SfRenderPass` 执行器），Rust 原生
宿主同享。

**评估（维持现状）**：
1. **记录-回放制的会话态归属绑定层**——RawPass 是 Python 面的
   记录-回放会话（pass 借用无法跨 Python 帧持有），`with` 块作用域 =
   Python 会话生命周期，缓存键（Arc 指针）在此层天然可得；
2. **引擎执行器加缓存需 per-replay-pass 状态**——回放每次 present
   新建 RenderPass（GPU 状态跨帧重置），引擎侧缓存若误跨帧 = 漏绑定
   正确性风险；双层去重（绑定层 + 引擎层）语义重复无增益；
3. **不破坏架构约束**——改 SfRenderPass 是通用命令编码器面，动它
   影响全部宿主。
**结论**：现状放置正确，记录本条为"评估后维持"。
